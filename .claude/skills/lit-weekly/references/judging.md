# 判断标准

PMHostX 做的是：**从 BGI PMseq（rRNA 去除建库）的单端短读长宏转录组数据里，
把宿主（人）mRNA 分离出来并定量，再以宿主表达为特征做机器学习建模，判别感染与病原类别**
（细菌 / 病毒 / 真菌 / 阴性）。标本覆盖**全血、肺泡灌洗液（BALF）、脑脊液（CSF）三种**，
不是只做脑脊液。

**按方法找文献，不按基因找。** 判断一条文献相不相关，看它和上面这条方法链的哪一环对得上
（建库、宿主信号分离、定量、建模、验证、标本），不看它碰没碰到某个特定基因。
**判词和页面里都不写 PMHostX 用了哪些基因**，也不写未发表的结果数字——这个仓库和页面是公开的。
同样不写队列名称或来源医院：判词关心的是方法，不是队列。
2026-10-28 之前这里写的是「样本是脑脊液」并列了一份基因清单，两条都已作废。

**方法上有一个已知隐患，判词常常要对上它：** 标本类型本身就能从宿主表达里被很好地区分出来，
三种标本合并算出来的指标会被系统性抬高，所以 PMHostX 的指标一律分标本报告。
凡是处理「标本 / 组织来源混杂」「跨标本迁移」「pooled vs 组内指标」的文献，都值得点明这一点。

判断一条文献该不该收，问一个问题：**它能不能用在论文的某个具体位置？**

## 收

| 类别 | 具体标准 | 常用位置 |
|---|---|---|
| 同题方法 | 从宏基因组/宏转录组数据里分离或定量宿主信号；宿主 vs 微生物信号 benchmark | Introduction 定位、Methods 引证 |
| 技术对偶 | 从宿主主导数据里提取**微生物**信号（你的镜像问题） | Introduction 论证难度 |
| 宿主去除 | 湿实验去宿主、rRNA 去除、参考库污染控制 | Methods 建库与比对 |
| 同任务建模 | 用宿主表达判别感染 / 非感染、细菌 / 病毒 / 真菌的分类器；特征选择、验证设计、跨标本或跨队列迁移 | Methods 建模、Discussion |
| 宿主标志物 | 宿主反应标志物与商业组合（MeMed BV / FebriDx / SeptiCyte / TriVerity 等）的临床性能 | 标志物判读与讨论 |
| 同标本 | 全血、BALF、CSF 任一种标本里的宿主转录组、mNGS 定量与判读阈值 | 结果对照 |
| 同病种 | 血流感染 / 脓毒症、下呼吸道感染、中枢感染的鉴别诊断与宿主标志物 | Discussion |
| 阴性/上限 | 诚实报告检出率低、AUC 高但判读失败、去宿主代价 | Discussion 局限（比正面证据更值钱） |

## 不收

**非人源宿主。** 这是最大的假阳性来源。

**判据是"这篇论文报告的基因表达数据来自哪个物种"，不是"它研究的是什么疾病"、
也不是"它建模的是不是人类疾病"。PMHostX 要的是人的基因。**

看到下面任何一个就排除：玉米/水稻/小麦等作物、珊瑚、鱼、虾、昆虫、土壤、海洋、
根际、反刍动物瘤胃、蜜蜂、家禽、兽医。**判断依据是宿主物种，不是标题里有没有
metatranscriptome。**

**动物疾病模型同样排除（2026-09-23 明确）。** 小鼠脑膜炎模型、JEV 小鼠神经免疫、
猪 Mx1、猪呼吸道类器官——即使建模的是人类疾病，它们测得的是**动物基因**，
不是人的基因，对 PMHostX 的宿主定量没有参考价值。看到 mouse/murine/mice/rat/
zebrafish/porcine/swine/organoid（非人源）就排除。

例外：**工具类论文不受此限。** rRNA 去探针设计（如 RiboZAP）、去宿主流程、建库策略
这类不报告任何基因、只报告流程的论文，归组 4，按流程价值判断。它们的"species-agnostic"
是特性不是缺点。

人源细胞系、人源类器官、人源临床样本、人源队列 —— 都可收。

**纯病原检测，无宿主维度。** 只做病原鉴定、没有宿主表达或宿主反应测量的，
一般不收。例外：作为**竞争或互补技术**出现在三种标本任一场景的（如 CSF 多重 PCR vs mNGS、
BALF 靶向测序 vs mNGS），可以收——中枢场景进组 3，其余按用途归组。

**纯微生物组/耐药组。** 没有宿主一层的，不收。

**综述性商业宣传。** 厂家自己发的、无原始数据的性能介绍，不收。

**与宿主反应、panel 基因、感染判别建模三者都无关的脓毒症研究。** 只做血清 CRP/PCT
且无新方法学、无新数据的，不收。

## 分组

| 组 | 名称 | 收什么 |
|---|---|---|
| 1 | 方法学核心 | 从宏组学数据提取宿主信号、宿主/微生物信号分离与 benchmark、宿主主导数据的预处理稳定性 |
| 2 | 标志物与 panel | 宿主反应标志物、四条商业产品线、宿主反应检测的临床性能 |
| 3 | 中枢感染 | CNS 感染（脑膜炎、脑炎）的宿主转录组与 mNGS 判读，多为 CSF 标本 |
| 4 | 建库、去宿主与参考库卫生 | rRNA 去除、湿实验去宿主、参考库污染、比对策略 |
| 5 | 背景、综述与研究框架 | 文献计量、领域综述、方法学框架、只用于引言定位的 |
| 6 | 诊断建模与分类器 | 用宿主表达或宏组学数据建模判别感染 / 病原类别；验证设计、跨标本迁移 |
| 7 | 窗口外，但必须知道 | 见下 |

拿不准归哪组时，问"论文里会在哪一节引用它"，按那一节归。

**组 3 是病种主题，不是标本分类。** 全血、BALF 的临床判读研究没有专门的组，按用途归：
标志物证据进 2、分类器 / 建模进 6、方法进 1。标本由页面上的「标本」筛选单独承担
（按标题 + 摘要自动识别），判断层不用为它分组。

## 必读门槛

标 `must_read: true` 的要同时满足两条：

1. **直接对上 PMHostX 的某个具体环节**——不是泛泛的"也做宿主反应"，
   而是能指出对上哪一步（建库、比对、定量、marker 判读、建模与验证、标本混杂、某个已知缺陷）。
2. **能改变当前的写法**——要么必须正面回应它（如最接近的已发表工具），
   要么它提供的数据会让某段论证更强或更弱。

宁可少标。每周最多标 1–2 条；一条都没有是正常的。
必读标多了就等于没标。

## 组 7：窗口外

`out_of_window: true` 的条目**不由 fetch.py 产出**——它们是概念上极近、
但发表日期在窗口外的论文，通常由人指定。只有以下情形才加：

- 该论文与 PMHostX 立意高度重合，写引言绕不开
- 或它是同一个 panel / 同一个方法的前序工作

加的时候必须写清**为什么破例**，以及它与窗口内条目的关系。
这类条目不需要 `added` 之外的处理，但要人工确认过日期确实在窗口外。

## why_html 的写法

对比一下：

> ❌ 该研究分析了宿主反应与感染的关系，具有一定参考价值。

> ✅ MeMed BV = **CRP + IP-10 + TRAIL** 三蛋白组合。前瞻队列
> （<3 岁不明原因发热）得 AUC 0.80、特异度 84.6%，但**敏感度仅 47.1%，被降钙素原反超**
> ——一个很有价值的蛋白层面上限/阴性结果，可在讨论中用于说明宿主标志物组合的边界。

要求：

- 点名**论文自己的**具体基因 / 具体数字 / 具体方法——那是已发表的内容，照写；
  但**不写它们和 PMHostX 用的基因重不重合**（「你 panel 里的 X」这类话不要写）
- 说清**和 PMHostX 哪个环节对得上**
- 如果它是个负面或受限结果，明确说出来——这类比正面结果更该被记住
- 用 `<strong>` 强调那一个最该被记住的点，但整段只强调一处
- 长度：1–3 句。不要复述摘要

## 日期与去重

- 日期一律用 `candidates` 里的 `pubdate`。它在 fetch 阶段已经过严格过滤
  （只认 `PubMedPubDate` 的 `pubmed`/`epublish`），你直接用即可。
- 去重靠 `data/seen.json` 的 id。id 优先取 DOI，无 DOI 取 PMID。
  **收录后务必更新 seen.json**，否则下周同一篇会再次出现。
- 同一篇论文的预印本与正式版可能是两条记录（不同 DOI）。都收，
  在 `why_html` 里点明是同一声明的两个版本。
