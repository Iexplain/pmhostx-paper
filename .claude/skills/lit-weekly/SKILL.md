# 每周文献增量

为 PMHostX（宏转录组宿主 mRNA 分离定量，并以宿主表达建模判别感染；全血 / BALF / CSF
三种标本）维护一份累积文献地图。流程分三层，**判断只发生在第二层**，其余全是确定性脚本。

## 怎么跑

```bash
bash scripts/run_weekly.sh
```

定时任务调它，手动跑也调它——两条路径完全一样。不要绕开它手工执行各步：
「抓取失败就停」「校验不过不提交」「失败回滚、last_run 不前移」这些约束都在脚本里，手工跑就没了。

| 退出码 | 含义 |
|---|---|
| 0 | 成功（含「本周 0 条」、「今天已跑过」） |
| 1 | 失败：数据已回滚，`last_run.json` 未动，下次从同一起点重来 |
| 2 | 另一次运行正在进行 |
| 3 | 已在本地提交但推送失败，下次运行一并推送 |

日志在 `logs/run_<日期>_<时刻>.log`，最后一行是 `RESULT: …`。
判断层的中间结果在 `work/<日期>/`：**同一天重跑会接着判，已判的不重复调用模型**。

测试用环境变量：`LIT_NO_PULL=1`、`LIT_NO_PUSH=1`、`LIT_LIMIT=N`（只判前 N 条新候选）、
`LIT_REJUDGE_LIMIT=N`、`LIT_MODEL=…`。测试请在仓库副本里做（工作区必须干净才会跑）。

## 硬约束

1. **绝不编造标识符。** PMID、DOI、发表日期、期刊、作者全部来自 `data/candidates_<date>.json`。
   现在由代码保证：判断层连 id 都不碰——每条在批内编序号 `k`，模型只回 `k` 和判断，
   `judge.py` 映射回 id，`apply_judgments.py` 从候选记录复制题录字段。
2. **抓取失败 ≠ 没有新文献。** `fetch.py` 退出码非 0 时整轮停止，**绝不**产出「本周无新增」。
   PubMed 抽风被静默当成「真的没新文献」，是这套流程最危险的失效模式。
3. **日期只认 `pubdate` 字段**（`pubmed` / `epublish` 的真实上线日期），不用期刊期号日期。
4. **只碰 `data/` 下的真相源，不手改 `site/`**——整个站点每次由 `build_page.py` 重建，手改会丢。
5. **检索范围是 PubMed；预印本是否被收录按 DOI 逐条实测，不按前缀整类推断。**
   2026-09-24 实测：`10.64898/…`（bioRxiv）里有拿到 PMID 的（42388796、42427735），
   也有回查仍无记录的（编号 6/29/30/31/35/36，只能人工维护）。
6. **这个仓库和页面是公开的。** 不写 PMHostX 用了哪些基因，不搬主仓库的清单或未发表数字，
   不写队列名。文献按 PMHostX 的**方法**找，不按基因找（见 `references/judging.md` 开头）。

## 流程（`run_weekly.sh` 做什么）

| 步 | 脚本 | 失败时 |
|---|---|---|
| 预检 | 加锁；工作区必须干净；`git pull --ff-only` | 停 |
| 1 抓取 | `fetch.py` → `data/candidates_<今天>.json` | 停（硬约束 2） |
| 2 补摘要 | `enrich.py` → `data/meta_cache.json` | 只告警：只影响页面摘要展示 |
| 3 判断 | `judge.py`：分批交给 `claude -p --tools ""` | 停；已判批次保留，重跑续判 |
| 4 写入 | `apply_judgments.py apply` → `seen.json`、`entries.json`、`weekly/<今天>.md`；`finalize` → `runs.json`、`last_run.json`；再跑 `validate.py` | 回滚，不提交 |
| 5 页面 | `build_page.py --queries-md` 重建整个 `site/` | 回滚 |
| 6 提交 | 只 add 流程改动的文件；提交后推送 | 推送失败退出码 3 |

**窗口。** `fetch.py` 从 `last_run.json` 的 `last_success` 次日抓到今天（含 60 天回溯余量），
不早于 `notes.json` 的 `window_start`。漏跑的周下次自动补上——这是设计，不要「修」成固定 7 天。
`added` 晚于上次成功运行的检索式，自动从窗口起点补抓。

**来源排除**由 `data/exclusions.json` 定义（目前排掉 Frontiers，DOI 前缀 `10.3389/`）。
过滤在取回之后做、不往检索式里塞 `NOT`，所以每轮排除了多少能量出来、条目留在
`excluded_by_policy` 里可查。**某周排除数异常大或明显该收的候选不见了，先看这个文件。**

**`last_run.json` 只有整轮成功才算数。** 它决定下次补漏起点，写早了会永久漏掉这段时间的文献。
它在第 4 步写入（校验要核对批次、周页要按 `runs.json` 生成、页面要显示「数据截至」），之后任何一步失败，
回滚都会把它恢复原样——所以「写入」和「生效」之间隔着提交这一步。

## 判断层

`judge.py` 每批 20 条，提示词是 `scripts/prompts/judge.md`，里面嵌入 `references/judging.md`
全文、已收录清单和待判条目。判断层**没有任何工具**——读不到文件、跑不了命令、改不了数据，
只回一个 JSON。每批回复先过机械检查，不过就带着错误说明重试；调用本身失败（限流）则等 30 / 60 / 90 秒再试。
四次不过整轮失败，每次失败的原始回复存在 `work/<日期>/failed_*.txt`：

- 序号 `k` 恰好是 1–N 各一次。2026-10-29 首轮正式运行前是让模型照抄 id，结果抄错（`…-08-030` → `…-08-30`）
  还编出过 `…-dupe-placeholder`，所以改成序号
- `v` ∈ in / out / skip，`why` 非空；收录的要有 `group`（1–7）、`must_read`、`why_html`
- 摘要为空才能写【无摘要】，而且必须写；摘要非空却声称无摘要 → 拦
- 判词里出现「你 panel 里的 X」→ 拦
- 已收录条目的重审只能输出 in（撤下条目要人工处理）

**接口拒绝处理**（`can't help with this`）连续两次时，批次对半拆开再判，拆到单条仍被拒，
这一条记为 **`pending`**（待人工）：台账里写 `v: pending`、进重审队列、周报列在「未能判断」，
下一轮自动重试**一次**；重试仍被拒就移出重审队列，留在台账里等人工判断
（找 `seen.json` 里 `v: pending` 的条目）。**不能记成 skip / out**——那等于声称「读过、不收」，是假账。
2026-10-29 首轮正式运行时有一批 20 条被连拒 4 次，整轮因此失败，才加的这条兜底。

判断标准、分组口径、排除规则全在 `references/judging.md`。改口径就改那个文件，
下一轮自动生效；**改了口径，要把受影响的旧判断放进重审队列**（见下）。

几条从教训里来的规则，判断层的提示词与 `judging.md` 已经写进去了，这里留底：

- **每条都读摘要。** 2026-09-24 之前允许凭标题分诊，578 条 skip 全建立在半截信息上，
  事后整批重审、改判收录 26 条。标题写 metatranscriptome 的可能是植物根际，
  标题平平的可能正是宿主反应研究——「像不像」不等于「是不是」。
- **`why_html` 是唯一无法自动化、也最有价值的产物。** 写清它做了什么、数字是多少、
  和 PMHostX 的哪个环节对得上（哪一步、哪个已知隐患）。不写「具有一定参考价值」这种话。
- **`v` 三个取值都要写理由。** `in` 收录 / `out` 属于想找的方向但不收 / `skip` 不属本论文范围。
  不收的也必须记：只记收录的话被拒的下周原样再来，候选池几百条，流程永远收敛不了。

## 重审队列

`data/rejudge.json` 的 `queue` 里放 `{"id", "reason"}`。下一轮运行时，这些条目连同新候选
一起交给判断层（带上次的判断与理由），处理完自动移出队列。用在：

- 口径变了：比如 2026-10-28 放开病原检测，把 33 条「无宿主维度」排除的旧判断放了进来
- 摘要回填了：当初凭标题写判词的条目，摘要补上后按摘要重写

已收录条目重审时组号沿用原组，只更新判词与必读标记。

## 校验（`validate.py`）

每轮写入后必跑，退出码非 0 就回滚、不提交。它专抓「不会让任何脚本报错、只会让台账变成假账」的错：

1. **编造的 id** —— 台账里出现既不在 `candidates_*.json`、也不在 `entries.json` 里的键。
2. **理由与记录矛盾** —— 声称「非人源宿主：猪」，而原始记录明确命中另一类物种、完全不命中猪。
   **判据是抓矛盾，不是抓缺失**：查不到任何一类只说明拿不出证据（草地螟的摘要写的是
   `destructive pest`），归入 `vague`，可见、可统计，但不拦。曾经写成「查不到就算造假」，
   一路误报——「论文里实际怎么称呼」是个开不完的清单。匹配前剥掉否定词和 `「」` 引用：
   那是理由在**谈论**物种，不是在**声称**物种。
3. **凭标题分诊的旧判词** —— 台账里不得再有以「标题分诊」开头的 `why`。
4. **声称「无摘要」必须为真**；`skip` / `out` 必须有非空理由。
   引用别处的说法用 `「」` 括起来（重审原因就是这样写进台账的），引号里的不算声称。

四条都注入过错误验证能拦住。

## 人工介入

**改检索式。** 改 `data/queries.json`，追加的检索式**写上 `"added": "YYYY-MM-DD"`**，
下一轮自动从窗口起点补抓；没写 `added` 的只回溯 60 天，窗口早期那段会被永久漏掉。
改完必须跑全量并集核对，确认旧收录都还在——只看「命中数变少了」不够
（2026-09-24 删 `differentiat*` 时丢过一篇收录，见那周周报）。

**运行失败。** 看日志最后的 `RESULT:` 行。修好后直接重跑 `run_weekly.sh`：
数据已回滚，已判的批次会复用。

**推送。** `pmhostx-paper` 可以自由提交推送；**`PMHostX` 主仓库只读不写**，
从那里读资料只用于理解方法，不把清单、数字、文件拷进本仓库。

## 常见情况

**候选为 0 条。** 正常。周报写「本周没有新收录」并照常提交——这跟「抓取失败」是两件事。

**某条候选确实没有摘要。** 判断层凭标题 + 期刊判断，理由带【无摘要】并注明需核对全文；
摘要回填后（`enrich.py` 会补到 `meta_cache.json`）把它放进重审队列。

**摘要读起来断在半句上**——断在 `"Seashore paspalum ("` 这种开括号处。那是 `fetch.py`
用 `t.text` 取摘要的老问题（丢掉行内标记之后的内容），已改用 `itertext()`。
**若再看到，先查 `fetch.py` 是不是又退回了 `t.text`**，不要当成「原文如此」。

**某类假阳性反复出现**（植物、珊瑚、兽医、肿瘤基因检测）。说明该收紧 `data/queries.json` 了，
看周报「未收录」一节的分布。
