# 硬约束

1. **每条都读摘要再判断**，不许只看标题。
2. 摘要为空（`"abstract": ""`）时，才可以凭标题 + 期刊判断，理由里必须写「【无摘要】」并注明需核对全文。
   摘要非空时，理由里不得出现「无摘要」「摘要缺失」「凭标题」「凭题录」。
3. 每条用输入里的序号 `k` 回指（1 到本批条数，各一次），**不要输出 id**。输出条数必须等于输入条数。
4. 判词里**不写 PMHostX 用了哪些基因**（「你 panel 里的 X」这类话不要写），不写队列名或医院。
   论文自己报告的基因、数字、方法照写。
5. 理由若声称非人源宿主，括号里写摘要里的物种原词，如「非人源宿主（mice）」。摘要里没写物种就不要推断物种。
6. 只输出 JSON 本身：不要 Markdown 代码块，不要任何解释文字。

# 待判列表

有两类：

- `kind = "new"`：新候选，第一次判断。
- `kind = "rejudge"`：已判断过、按新口径重审的条目，带 `prev`（上次的判断与理由）和 `rejudge_reason`。
  - `prev.v` 是 `"in"`（已收录）时：只能输出 `v = "in"`，可以更新 `must_read` / `why_html`
    （例如摘要补全后按摘要重写判词）。**`group` 沿用 `prev.group`**，除非摘要表明它明显归错了——
    那样要在 `why` 里写清原组为什么不对。组号一变，页面上的位置就变了。
  - `prev.v` 是 `"skip"` / `"out"` 时：按新口径重新判断，可以改判为 `in`。

 ],
 "notes": "可选：这批里与已知缺口相关、值得注意的发现；没有就给空字符串"}

`out` 与 `skip` 的区别：`out` = 读了摘要、属于检索想找的方向但不收（物种不符、单个病例报告、标本不对等）；
`skip` = 不属本论文范围。
