## 两处流程修正

**1. 物种校验的判据方向改对了（这一条返工了三次）。**

起因是一条奶牛子宫炎论文的理由写了「非人源宿主：牛」，校验却报"记录里找不到该物种"——
词表只收了 `bovine|cattle`，而原文通篇是 **`dairy cows` / `Holstein cows`**。

于是补词表，然后一路误报：补了 `cow|cows|dairy|heifer|Holstein`，漏了 `dairy cows`；
补了 `\bfish\b`，漏了 `Finfish`；补了 `sorghum|rice`，漏了 `plant` / `grape` /
`legume` / `rhizosphere` / `mycorrhiza`。**每一次都在把正确的理由判成造假**——
因为"论文里实际怎么称呼"是个开不完的清单。

真正的教训是：**「查不到」只说明拿不出证据，不等于「证据矛盾」。**
所以判据反了过来：只抓矛盾——理由声称 A 类，而记录明确命中另一类、且完全不命中 A；
哪一类都没命中则归入 `vague`（页面可见、可统计、不拦）。
同时补了第二个洞：历史台账写英文括号（`非人源宿主（mice）`），中文键名一个都不匹配，
这批记录**从来没被校验过**；改为理由侧中英文同时识别后，实际参与比对的记录从 0 条变成 151 条。

第三次返工是键名本身：新加的"人类"这一类，单字键 `人` 会子串命中每条理由里的
"非**人**源宿主"，一开就报 39 条假问题；键名改成「人类」后，又轮到理由里的
"非**人类**临床样本"命中自己那句否定。**否定词必须先剥掉再匹配。**

三种错法各注入一次验证过，都能正确抓出并退出码 1。

**2. 预印本口径改对。** 原来写的是"bioRxiv `10.64898/…` 永远没有 PubMed 记录"，
这批实测推翻：**同一天**两条 bioRxiv 预印本已有 PMID（42388796、42427735）并被正常收录，
而清单里原有 7 条标 `pubmed_indexed: false` 的条目用 DOI 回查**仍全部无记录**。
所以规则改成 **按 DOI 逐条实测，不按前缀整类推断**——前缀不能作为是否被收录的依据。

## 摘要截断缺陷：一个不报错的错

重审途中撞上更根本的问题。抓取脚本取摘要用的是 `t.text`：

```python
abstract = clean(" ".join((t.text or "") for t in art.findall(".//Abstract/AbstractText")))
```

`t.text` 只返回元素内**第一个子标签之前**的文字。PubMed 的结构化摘要里到处是
`<i>`（学名）和 `<sup>`（如 `CD45RB<sup>low</sup>`）这类行内标记，标记之后的全部内容
都存在子节点的 `.tail` 里——**被整个丢掉**。症状是摘要齐刷刷断在
`"Seashore paspalum ("`、`"The common bed bug ("` 这种开括号处：
688 条候选里 **134 条**的摘要因此残缺，判断层拿半截摘要做分诊。

改用 `itertext()` 后从本地 `raw/` XML 回填，**389 条**拿到完整摘要，
其中 16 条一直标着"无摘要"的其实一直有。回填后逐条检查了受影响最重的
**99 条判词建立在空摘要 / 残摘要上的记录**：**0 条改判**——
缺陷损害的是判词质量，没有损害收录结果。另外 16 条无摘要记录的判词已按补全后的摘要重写。

它抓到两条**我自己写错的判词**：

- `10.1016/j.isci.2026.116418` 写「非人源宿主（mouse）」，摘要原文是
  "macrophages from **people with type 1 diabetes**"——是**人类**研究。
- `10.1111/nyas.70329` 写「非人源宿主（mouse）」，摘要只说 "upon encephalitogenic stress"，
  **通篇没有出现过任何物种**——那是无据推断，不是读错。

两条都已改写并注明原因。这也正是物种校验存在的理由：理由说"非人源"、实际是人群研究，
是最严重的一种错法。
